# xmatch report (tools/xmatch.py; outputs only under work/xmatch/)

Method: compile library C from other public DS decomps with our mwcc 1.2p2 (4 variants: arm/thumb x -O4,p/-O4,s),
mask relocs (tools/sdk_match.py masks + xmask), hash-match against queue rows todo/fail_sonnet/fail_haiku/blocked that
docs/sdk_map.txt does not list as unique/fuzzy100 (3,164 candidates at the final run; the set shifts when sdk_map.txt
is regenerated). Then emit source, remap symbols to ours, verify with tools/try.

## Verified exact matches (tools/try = MATCH): 24, in work/xmatch/matches/<func>.c
By queue status: fail_sonnet 16, blocked 8, todo 0, fail_haiku 0.
- 21 are hand-written SDK `asm` functions (mwcc inline asm, `#pragma thumb off`): MI_memory (MIi_CpuCopy32,
  MIi_CpuClearFast, MIi_CpuCopyFast, MI_Copy32B/36B/48B/64B, MI_CpuFill8, MI_CpuCopy8), MI_SwapWord, OsCountZeroBits,
  OS_Enable/Disable/RestoreInterrupts(+_IrqAndFiq), OS_GetCpsrIrq, OS_GetProcMode, OS_SpinWait, OS_Halt,
  OSi_AlarmHandler. Project rule is "asm only for BIOS swi stubs", so integrating these is a policy decision
  (mrs/msr/swp/clz/mcr cannot be written in C; queue already marks them "not C").
- 3 are real C: func_0208f09c CRYPTO_RC4Init, func_0208f0f0 CRYPTO_RC4FastInit (pret/pokeplatinum lib/crypto, default
  flags -O4,p thumb), func_0208641c OS_WaitIrq (pokediamond; needed `irqFlags & *HW_INTR_CHECK_BUF` operand order and
  data_02fe0000/data_02fe0544 externs).
Ready-to-integrate files already have FFC names; the asm ones use a small typedef/define preamble (u8/u16/u32,
OSIntrMode, HW_PSR_*), which should be replaced by project headers.

## Problems / notes
- pokediamond is NitroSDK 3.x built with mwcc 2.0/sp1; FFC is SDK 5 / 1.2p2, so only tiny stable leaf functions match.
  Low yield is expected: libntr already covers the SDK-5 C.
- sdk_match.mask bug: ARM `bl` in a source object vs `blx` (to a Thumb callee) in the ROM differ in the condition byte
  (0xEB vs 0xFA/0xFB) and are not masked, so such functions never hash-match. tools/xmatch.py xmask masks the whole word.
  That is how OS_WaitIrq was found; applying the same fix to tools/sdk_match.py could raise sdk_map coverage for ARM
  functions that call Thumb callees (not done; not my files).
- docs/sdk_map.txt was regenerated by another agent during the run, so candidate counts vary (3,164 vs 3,808).
- Failures logged in work/xmatch/failed.txt.

Re-run: `python3 tools/xmatch.py compile && python3 tools/xmatch.py match && python3 tools/xmatch.py emit`
(emit handles only simple `asm` leaf functions; C hits were remapped by hand).
